# Verification Claims and Acceptance Authority

Verification evidence distinguishes observed agent behavior from technical enforcement. An agent's refusal or compliant response is behavioral evidence only; a restriction is `ENFORCED` only when a supported harness, operating-system, or external platform control is verified to block violations. External controls are reported separately from framework controls. This extends, and does not weaken, [ADR 0005](0005-verified-enforcement-boundaries.md).

An implementation agent may run tests and prepare evidence but cannot change its own acceptance criteria, waive its own findings, or self-certify acceptance. For the single-owner MVP, the project owner/operator performs a separate evidence-review step and explicitly accepts P0H. This is procedural and session-level separation, not independent human or identity-level separation. A Coordinator or model recommendation is not acceptance authority.

Acceptance does not directly change canonical state. The State Engine remains the sole authority that validates and records approved project-state transitions and maintains the rebuildable projection; agents and the Coordinator submit requests only ([ADR 0002](0002-single-writer-state-transitions.md)). Material implementation verification details are bound to the immutable, version-bound task packet; material changes require a revised packet ([ADR 0004](0004-version-bound-task-context.md)). Operational testing procedures are defined in [the P0 verification protocol](../testing/p0-verification-protocol.md), not in this ADR.
